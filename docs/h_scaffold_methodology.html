01 · 핵심 아이디어와 논문과의 차이

BPE는 자주 등장하는 인접 토큰 쌍을 반복해서 합칩니다. 어떤 중간 토큰은 더 긴 토큰을 만드는 데 유용하지만, 병합이 진행된 뒤에는 독립적으로 거의 남지 않을 수 있습니다. Scaffold-BPE는 이런 중간 토큰을 병합용 어휘에는 유지하되, 최종 모델 입력에서는 분해하여 제거합니다.

원 논문은 일반 토큰과 scaffold 토큰을 구분합니다. 학습에서는 병합 후 자식 토큰의 잔여 빈도를 다음 큐 헤드의 빈도와 비교하고, 인코딩에서는 전체 확장 어휘를 사용한 병합 후 남은 scaffold를 일반 토큰으로 분해합니다. 논문 Algorithm 1·2

H-Scaffold의 추가 설계: scaffold를 L1과 L2로 나누는 0.5 × f(Qhead) 경계, L2를 먼저 분해하는 절차, 그 이후 L0/L1만 허용하는 재병합은 이 프로젝트에서 추가한 규칙입니다. 원 논문의 규칙으로 인용하면 안 됩니다.
항목Scaffold-BPE 논문현재 H-Scaffold 구현
토큰 구분일반 / scaffoldL0 / L1 / L2
scaffold 판정잔여 빈도 < 큐 헤드 빈도같은 기준을 바탕으로 scaffold를 0.5 경계로 추가 구분
인코딩전체 병합 → scaffold 분해전체 병합 → L2 분해 → 제한된 재병합 → L1 분해
최종 모델 입력일반 토큰만L0만

설계 의도는 잔여 빈도가 더 낮은 L2를 먼저 해체하여 다른 이웃과 결합할 기회를 만들면서, L1은 두 번째 병합까지 중간 구성요소로 사용할 수 있게 하는 것입니다. 이것이 반드시 토큰 수 감소나 모델 성능 향상으로 이어진다는 보장은 없습니다.

02 · 토큰·빈도·자료구조

L0 · 최종 어휘

모델이 입력받는 토큰입니다. 목표 vocabulary 크기는 L0 개수로 계산합니다. 기본 256개 byte와 특수 토큰도 여기에 포함됩니다.

L1 · 중간 scaffold

첫 번째 병합과 두 번째 병합에 사용할 수 있습니다. 마지막 분해 단계에서 제거됩니다.

L2 · 먼저 분해할 scaffold

첫 번째 병합에는 참여합니다. 그 결과에 남아 있으면 L0/L1 조각으로 분해하며, 두 번째 병합에서는 L2를 생성할 수 없습니다.

텍스트는 GPT-2 정규식으로 pretoken을 나누고, 각 조각을 UTF-8 bytes로 표현합니다. pretoken은 공백 기준 단어와 동일하지 않으며, 문자·숫자·기호·공백과 축약형 패턴으로 구분되는 단위입니다.

자료구조 / 기호의미
tokens[id]내부 토큰 ID에 대응하는 byte 문자열.
levels[id]현재 L0/L1/L2 상태. 저장된 최종 상태를 인코딩에 사용합니다.
token_counts[t] / f(t)현재 병합된 학습 시퀀스에서 토큰 t가 남아 있는 횟수. pretoken 출현 빈도로 가중합니다. 원문 부분 문자열의 전체 등장 횟수가 아닙니다.
pair_counts[(a,b)]현재 시퀀스의 인접 쌍 빈도. 학습 병합 후보의 우선순위에 사용합니다.
Q빈도 우선 힙. 병합할 쌍과 재활성화를 기다리는 scaffold 토큰을 함께 저장합니다.
f(Qhead)오래된 힙 항목을 제외한, 현재 유효한 최상위 항목의 빈도. 반드시 쌍의 빈도만을 뜻하지는 않습니다.
merges학습 중 기록한 병합 목록. Python 인코딩의 병합 순위는 이 목록의 순서입니다.
parents[t]t를 구성한 자식 쌍의 목록. 분해 시 따라가는 경로이며 여러 대안이 있을 수 있습니다.

확장 어휘는 L0+L1+L2 전체입니다. 최종 모델 ID는 정렬된 L0 내부 ID에 연속 번호를 다시 부여하여 만듭니다. 따라서 내부 토큰 ID와 모델 입력 ID는 구분해야 합니다.

03 · L0/L1/L2 판정 규칙

병합 (a,b) → t를 실제 시퀀스에 적용한 뒤, 소비된 a와 b의 빈도를 차감합니다. 이때의 잔여 빈도와 갱신된 큐 헤드 빈도를 비교합니다. 아래 식은 검사 대상인 L0 자식 토큰에 적용되는 분류 규칙입니다.

q = f(Qhead), r = f(child), α = 0.5
조건결과q = 100 예시
r ≥ qL0 유지r = 100, 120
0.5q ≤ r < qL1로 변경r = 50, 75, 99
r < 0.5qL2로 변경r = 0, 25, 49

경계는 엄격한 < 비교입니다. 정확히 0.5q이면 L1이고, 정확히 q이면 L0를 유지합니다. 계수 0.5는 현재 trainer에 하드코딩되어 있으며 학습 함수의 조절 가능한 인자로 노출되어 있지 않습니다.

경계값 확인 · L0 자식 토큰을 가정

학습 상태 전체를 재현하는 도구가 아니라, 위 조건문의 수치 예시입니다. 기본 byte·특수 토큰은 제외합니다.

q = 100, r = 49 → L2
최종 어휘 전체가 위 식으로 항상 정렬되는 것은 아닙니다. 코드는 매 단계에서 모든 토큰을 다시 분류하지 않고, 방금 병합에 참여한 자식만 검사합니다. 기존 상태와 재활성화 이력도 영향을 줍니다. 따라서 최종 L1/L2를 마지막 Qhead 하나로 다시 계산한 구간으로 해석하면 부정확합니다.

근거: trainer.py:246–269.

04 · 학습 알고리즘과 상태 전이

  1. 초기화: 기본 byte 256개와 특수 토큰을 L0로 고정합니다. pretoken별 byte 시퀀스에서 토큰 빈도·인접 쌍 빈도와 쌍이 등장하는 위치를 집계합니다.
  2. 큐에서 다음 항목 선택: 유효한 최고 빈도 항목을 꺼냅니다. 오래된 빈도나 이미 무효화된 상태의 힙 항목은 버립니다.
  3. scaffold 토큰 항목이면 재활성화: 해당 토큰을 L0로 올리고 visible count를 늘린 뒤 다음 반복으로 넘어갑니다. 이 분기에서는 시퀀스를 병합하지 않습니다.
  4. 쌍 항목이면 출력 토큰 확인: 두 자식의 bytes를 이어 붙입니다. 새 토큰이면 L0로 추가합니다. 같은 bytes의 기존 scaffold 토큰이면 L0로 재활성화한 뒤 다음 반복으로 넘어가는 별도 분기가 있습니다.
  5. 병합과 빈도 갱신: 진행 가능한 쌍의 병합 이력을 기록하고, 해당 쌍이 있는 학습 시퀀스에서 왼쪽부터 겹치지 않게 병합합니다. 인접 쌍 통계와 토큰 잔여 빈도를 갱신합니다.
  6. 자식 상태 갱신: 이미 scaffold인 자식의 유효한 잔여 빈도를 큐에 반영한 뒤 Qhead를 읽습니다. 기본 byte·특수 토큰을 제외한 두 자식에 L1/L2 판정을 적용합니다.
  7. 종료: L0 개수가 목표 어휘 크기에 도달할 때까지 반복합니다. L1/L2로 내릴 때 L0 개수가 줄기 때문에 확장 어휘는 목표 크기보다 클 수 있습니다.
# 분류 부분을 중심으로 정리한 의사코드
실제 병합 및 빈도 갱신
기존 scaffold 자식의 갱신된 양수 빈도를 Q에 삽입
q = 유효한 Qhead의 빈도  # 유효 항목이 없으면 0

for child in {left, right} - 기본 byte/특수 토큰:
    if level[child] == 0 and f(child) < q:
        level[child] = 2 if f(child) < 0.5*q else 1
        visible_count -= 1
        if f(child) > 0:
            Q에 child 삽입
    elif level[child] == 1 and f(child) < 0.5*q:
        level[child] = 2

기존 L1은 조건에 따라 L2로 내려갈 수 있습니다. 반대로 빈도 비율만 보고 L2를 L1로 올리는 분기는 없습니다. L1/L2는 큐에서 선택되거나 기존 scaffold 출력 토큰을 다시 활성화하는 경로를 통해 L0로 복귀할 수 있습니다.

두 자식이 같은 토큰인 병합에서는 동일 빈도 카운터를 두 번 차감합니다. 예를 들어 (a,a) → aa 한 번은 a 두 개를 소비하기 때문입니다. 쌍 빈도에는 겹친 인접 쌍이 포함될 수 있으므로, 잔여 빈도의 차감에는 실제로 적용한 비중첩 병합 횟수를 사용합니다.

05 · 인코딩의 다섯 단계

① 입력 준비특수 토큰 구간 분리
정규식 pretokenization
UTF-8 bytes
② 전체 병합L0/L1/L2를 모두 이용하여 긴 토큰 구성
③ L2 분해남아 있는 L2를 L0/L1 자식 열로 변환
④ 제한 재병합L0/L1을 출력하는 규칙만으로 BPE 재실행
⑤ L1 분해남은 L1을 L0 자식 열로 변환하고 모델 ID로 매핑
sequence = BPE(bytes, max_output_level=2)

early = concat(demolish(token, max_level=1) for token in sequence)
sequence = BPE(early, max_output_level=1)

final = concat(demolish(token, max_level=0) for token in sequence)
return map_to_model_ids(final)

“L2를 먼저 분해한다”는 첫 BPE 전에 제거한다는 뜻이 아닙니다. 첫 BPE에서는 L2도 더 긴 토큰을 만드는 데 사용할 수 있습니다. 그 과정이 끝났을 때 독립 토큰으로 남은 L2만 L1보다 먼저 분해합니다.

이미 L2를 재료로 만들어진 L0 토큰은 그대로 유지합니다. 분해 함수는 현재 토큰의 level이 허용 범위이면 즉시 반환하므로, L0 내부에 과거 L2 구성요소가 있었다는 이유로 병합 이력을 거슬러 올라가 분해하지 않습니다.

두 번째 BPE가 끝난 후 L1을 분해하며, 그 뒤에 세 번째 BPE는 없습니다. 인코딩 도중 입력 텍스트의 빈도를 다시 세어 level을 바꾸지도 않습니다. 학습 모델에 저장된 level을 사용합니다.

근거: tokenizer.py:100–136, 148–161. 위 의사코드는 Python 경로의 핵심이며 백엔드별 구간 처리는 07절에서 구분합니다.

06 · 분해 알고리즘의 정확한 의미

_demolish_token(token_id, max_level)은 현재 토큰이 허용 level 이하면 그대로 반환합니다. 허용되지 않는 토큰이면 parents에 저장된 각 자식 쌍을 재귀적으로 분해합니다.

demolish(t, k):
    if level[t] <= k:
        return [t]
    candidates = []
    for (left, right) in parents[t]:
        candidates.append(demolish(left,k) + demolish(right,k))
    return min(candidates, key=(조각 수, 내부 ID 열))
  • L2 분해: k=1이므로 L0/L1에 도달하면 멈춥니다.
  • 최종 분해: k=0이므로 L0에 도달할 때까지 분해합니다.
  • 복수 경로 선택: 저장된 자식 경로들 중 결과 조각 수가 최소인 것을 선택합니다. 길이가 같으면 내부 ID 열의 사전순으로 결정합니다.
  • 캐시: 토큰 ID와 허용 level별 결과를 캐시하여 반복 분해 비용을 줄입니다.
  • 오류: 분해해야 하는 scaffold에 저장된 자식 경로가 없으면 예외가 발생합니다.
여기서 “최소 조각 수”는 저장된 병합 이력으로 도달할 수 있는 분해들 중 최소입니다. 전체 vocabulary를 이용해 가능한 모든 byte 경계 분할을 탐색하는 전역 최적화가 아닙니다. 분해 경로를 선택할 때 주변 토큰과의 향후 재병합 결과도 미리 평가하지 않습니다.

근거: tokenizer.py:100–111, trainer.py:210–211.

07 · 재병합 순위와 주변 탐색 범위

고정된 좌우 윈도는 없다

_apply_bpe는 전달받은 시퀀스의 모든 인접 쌍을 검사합니다. 저장된 병합 규칙이 있고, 출력 토큰 level이 허용 범위인 후보 중 학습 병합 순위가 가장 빠른 쌍을 선택합니다. 선택한 쌍의 비중첩 출현들을 왼쪽부터 병합하고, 바뀐 시퀀스를 다시 검사합니다.

새로운 인접 쌍을 계속 만들 수 있으므로 병합 영향은 여러 토큰에 걸쳐 연쇄적으로 이어질 수 있습니다. 하지만 떨어진 토큰을 건너뛰어 합치거나, 학습에 없는 병합 규칙을 새로 만들지는 않습니다. 인코딩 시점의 출현 빈도나 의미적 유사도도 순위 기준이 아닙니다.

“재병합을 한 번 더”의 의미: 인접 쌍을 딱 한 번 합치거나 한 번 훑고 끝내는 것이 아닙니다. L0/L1을 출력하는 허용 병합이 더 이상 없을 때까지 BPE 루프 한 차례를 완료합니다.

L2 분해·재병합 범위pretoken 하나씩 처리특수 토큰으로 분리된 일반 텍스트 구간의 토큰 열 전체
재병합 함수동일한 Python _apply_bpe(..., max_output_level=1)

고속 경로는 첫 병합 이후 pretoken별 경계 정보를 전달하지 않고, 일반 텍스트 구간의 결과를 한 시퀀스로 분해·재병합합니다. 따라서 재병합 함수는 pretoken 경계에 놓인 인접 쌍도 검사할 수 있습니다. 특수 토큰 경계는 encode()가 따로 구분하므로 넘지 않습니다.

확인된 사실과 검증할 문제를 구분해야 합니다. 두 경로의 재병합 입력 범위가 다른 것은 코드로 확인됩니다. 그러나 경계에서 실제 병합하려면 해당 쌍의 허용 병합 규칙이 존재해야 합니다. 범위 차이만으로 결과 불일치가 발생했다고 단정할 수 없습니다. 동일하게 첫 병합의 rank 구성 방식 차이도 모든 모델에서 동등한지는 별도로 확인해야 합니다.

근거: tokenizer.py:15–17, 29–52, 67–98, 113–161.

08 · 단계별 예시

아래 토큰과 규칙은 작동 원리를 보여 주기 위한 가상 예시입니다. 저장된 실험 모델에서 추출한 실제 인코딩 결과가 아닙니다.

분해된 조각이 기존 이웃과 합쳐지는 경우

가정:
  X = uv, X는 L2
  A, u, v, B는 L0
  (A,u) → Au, (v,B) → vB 규칙이 있으며 Au, vB도 L0

① 첫 BPE의 결과             [ A | X(L2) | B ]
② 남은 L2를 분해            [ A | u | v | B ]
③ L0/L1 출력만 허용해 재병합  [ Au | vB ]
④ 남은 L1이 없으므로 출력     [ Au | vB ]

L2였던 X의 내부 조각 u와 v만 다시 보는 것이 아닙니다. u는 왼쪽 A와, v는 오른쪽 B와 병합될 수 있습니다. 원래 (u,v) → X 규칙은 출력이 L2이므로 두 번째 BPE에서 금지됩니다.

L1은 마지막까지 중간 조각으로 남을 수 있다

첫 BPE 결과:       [ X(L2) ]
X의 저장된 자식:    [ Y(L1), z(L0) ]
Y의 저장된 자식:    [ a(L0), b(L0) ]

L2 분해:          [ Y, z ]       # Y는 여기서 유지
제한 재병합:       [ Y, z ]       # 허용된 병합이 없다고 가정
최종 L1 분해:      [ a, b, z ]    # 이후 추가 BPE 없음

이처럼 L2를 L0까지 무조건 분해하는 것은 아닙니다. 먼저 L0/L1까지만 풀고 재병합 기회를 준 다음, 마지막에 L1을 제거합니다.

09 · 검증 범위와 미확정 사항

코드 확인기존 테스트 9개 통과2026-10-07 검토에서 프로젝트 가상환경으로 .venv/bin/pytest -q를 실행했고 기존 테스트 9개가 통과했습니다. 이 문서 작성을 위해 학습이나 모델 재생성은 수행하지 않았습니다.

기존 테스트가 확인하는 항목범위
저장·로드, encode/decode 복원, 어휘 크기작은 합성 코퍼스로 학습한 세 variant
최종 출력에 scaffold가 없는지hierarchical의 출력 내부 ID가 모두 L0인지 확인
확장 어휘와 snapshot 크기작은 목표 어휘 크기에서 검증
tiktoken / Python 결과 일치세 variant에 대해 지정된 소수의 예제 문자열 비교

팀과 합의해야 할 설계 질문

  1. α=0.5의 지위: 최종 채택한 값인지, 임시 실험값인지? 선정 근거와 다른 경계값 비교 결과가 있는지?
  2. 조기 분해의 시점: “전체 BPE 완료 후 잔여 L2 분해”가 의도인지? 병합 도중 L2를 즉시 분해하려는 구상과는 다릅니다.
  3. 재병합의 범위: pretoken 내부로 제한할지, 일반 텍스트 구간 전체를 대상으로 할지? 두 백엔드의 범위를 일치시킬지?
  4. level 갱신 정책: 병합 자식만 검사하고 L1→L2 및 scaffold→L0 경로를 두는 현재 정책이 의도한 계층 동작인지?
  5. 분해 대안 선택: 병합 이력 안에서 최소 조각 수를 택하고 ID로 동률을 해소하는 규칙이 충분한지? 주변 재병합까지 고려하는 최적화가 필요한지?

추가 검증으로 구분할 수 있는 문제

  • 경계값 바로 아래·정확히 경계·바로 위의 분류와, L1→L2·L2→L0 재활성화 경로를 직접 검증합니다.
  • 한글·다국어·축약형·숫자·공백·기호·특수 토큰 경계에서 실제 32K/64K 모델의 두 백엔드 결과를 비교합니다.
  • 여러 분해 경로와 동률 사례에서 최소 분해 규칙을 확인합니다.
  • α를 바꾸는 실험, 재병합을 제거한 실험, 같은 scaffold 표시를 사용한 실험을 분리하여 효과를 측정합니다. 이러한 실험은 현재 문서에서 수행한 결과가 아니라 제안입니다.

측정 지표는 최종 토큰 수·fertility, bytes/token, 인코딩 처리량, 확장 어휘 크기와 level별 분포, LM의 bits-per-byte 등을 함께 보는 것이 좋습니다. 입력 토큰 체계가 달라질 수 있으므로 token-level perplexity 수치 하나만으로 tokenizer 간 우열을 결론 내리지 않아야 합니다.

설계 해석의 한계: L1과 L2 모두 visible vocabulary에서 제외됩니다. 따라서 “L2로 나눈 것 자체가 L1보다 vocabulary 자리를 더 절약한다”는 설명은 부정확합니다. 계층 구분은 분해 시점과 허용 재병합 경로를 바꾸며, 현재 코드는 기존 L1을 L2로 내리는 조건도 추가합니다. 성능 차이의 원인은 통제 실험으로 확인해야 합니다.
